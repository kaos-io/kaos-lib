# L-E07 StepDeclaration

**Level: error.** A step does not say what it is, what it reads or what it writes in a form the platform accepts.

## What it checks

- Every `step()` has `kind=`, one of `ingest`, `transform`, `train`, `evaluate`, `publish`, `control`.
  When no step of the pipeline has a `kind=`, the message adds that the app was made before the current pipelines and
  has to be created again from the template. When some steps have one, a step without it gets the plain message.
- `inputs=` is a list of names: the config values that hold a dataset reference.
- A step name, an input name and a name in `produces=` use lowercase letters, digits and hyphens, are at most 40
  characters long and do not start with `kaos-`.
- `produces=` is a list of `model("name")`, `artifact("name")` or `dataset("name")`, each name used once, in
  lowercase letters, digits and hyphens, and not starting with `kaos-`.
- A dataset name has 3 to 40 characters: it is stored as `dataset-<app>-<name>`.
- A step does not read and write one name: an `inputs=` name is not also a name in the step's own `produces=`.
- A step has its folder: `steps/` plus the step's name with every hyphen written as an underscore (`model-eval` is
  `steps/model_eval/`). Checked in a repository that has a `steps/` folder.
- `dataset("name", of=...)` is not used: `of=` is reserved for a later release.
- A step does not have an input and something a step it needs produces under the same name, and two steps it
  needs do not produce the same name: `step.input("name")` could then mean either.
- A step needs at most ten steps, and can read at most sixteen datasets by name (its inputs and the datasets
  produced by the steps it needs).
- An input is a top-level value in `config/` that holds text, not a section (`train:` with settings below it).
- A step keeps to the contract of its type ([Step types](../step-types.md)). Each rule has a sentence that says
  what to do:
    - `Step 'x': an ingest step brings data in, so it produces a dataset. Add produces=[dataset("name")].`
    - `Step 'x': a transform step turns data into something. Add produces=[...] with a dataset, a model or an artifact.`
    - `Step 'x': a train step produces a model. Add produces=[model("name")], or give the step the kind of the work it does (ingest, transform, evaluate, publish, control).`
    - `Step 'x': an evaluate step writes reports only, so it may not produce a dataset or a model. Use kind="transform" for a step that makes a dataset, kind="train" for one that makes a model.`
    - `Step 'x': a publish step delivers a result and produces nothing here. Remove produces=, or give the step the kind of the work it does.`
- A `control` step takes no `inputs=` and no `produces=`: it steers the run and handles no data.
- Two steps do not produce the same `dataset(...)`: a dataset has one writer.
- A step does not have one of the names the platform keeps for itself ([the limits](../contract.md#the-limits)).

## Why it matters

The platform labels every step with its type, pins each input to one exact version when the run starts, and
gives the step write access to exactly what it declares in `produces=`. A step that declares none of this
cannot be rendered.

## Example

```python
step("prepare", inputs=["dataset"])                                 # no kind
step("prepare", kind="preprocess")                                  # not a kind
step("prepare", kind="transform", produces=["clean"])               # produces takes dataset("clean")
step("train", kind="train", produces=[artifact("log")])             # a train step produces a model
```

## How to fix

```python
prepare = step("prepare", kind="transform", inputs=["dataset"], produces=[dataset("clean")])   # folder steps/prepare/
train = step("train", kind="train", needs=[prepare], gpu=True, produces=[model("model")])
```
