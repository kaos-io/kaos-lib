# L-I04 StepsBuiltInALoop

**Level: info.** Some steps are built in a loop or a call, so the checks could not read them.

## What it checks

A `step(...)` call whose name is not a plain text, for example `step(f"trial-{i}", ...)` inside a `for` loop. The checks
that read a step's arguments (its kind, the datasets it reads and writes, its folder, its limits) need the name and the
arguments written out. For a step built in a loop they stay silent.

## Why it matters

A clean report does not cover those steps. A mistake in them shows when the pipeline is rendered, or when the step runs.

## How to use it

Nothing is wrong. To have every check read a step, write the step out with a plain name. For a sweep, a loop inside one
step is simpler than one step per trial: see [Sweeps](../sweeps.md).
