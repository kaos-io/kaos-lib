# L-E01 TooLongNotResumable

**Level: error.** A step asks for more time than one run of the HPC (Slurm) site allows, and it cannot continue.

## What it checks

A GPU step sets `hpc_time_limit` above the longest run the site allows (2 days by default), and it is not resumable: it
is not declared `resumable`, and its code shows no use of checkpoints.

## Why it matters

When the time limit passes, the job is stopped. A step that cannot continue from a checkpoint loses its work. The platform
refuses such a step when it is submitted, so the run would fail after your pull request is merged.

## Example

```python
train = step("train", gpu=True, hpc_time_limit="72h")     # 3 days; the longest run is 2 days
```

## How to fix

Either make the step resumable, so the platform continues it in a new job from its last checkpoint:

```python
train = step("train", gpu=True, hpc_time_limit="72h", resumable=True)
```

and save checkpoints (see [Long runs on HPC (Slurm)](../checkpoint.md)), or set `hpc_time_limit` to the longest run or less.

## Limits of the check

The check finds checkpoint use by reading the step's code for `kaos_lib.checkpoint` or a training framework the library
hooks automatically (Ultralytics, PyTorch Lightning, Hugging Face Trainer). The longest run comes from your project when
you give `--context`; otherwise the built-in default of 2 days applies. It is skipped when the catalogue says your
project has no HPC (Slurm) site.
