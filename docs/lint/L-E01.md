# L-E01 TooLongNotResumable

**Level: error.** A step asks for more time than one run of the HPC (Slurm) site allows, and it cannot continue.

## What it checks

A GPU step sets `walltime` above the longest run the site allows (2 days by default), and it is known not to be
resumable: it sets `resumable=False`, or the platform recorded that a continuation of the step did not get past its
checkpoint (it is not declared `resumable` and no continuation of it has ever worked). When the step's resumability is
not known, the check stays silent: it never guesses from the code.

## Why it matters

When the time limit passes, the job is stopped. A step that cannot continue from a checkpoint loses its work. The platform
refuses such a step when it is submitted, so the run would fail after your pull request is merged.

## Example

```python
train = step("train", gpu=True, walltime="72h", resumable=False)   # 3 days; the longest run is 2 days
```

## How to fix

Either make the step resumable, so the platform continues it in a new job from its last checkpoint:

```python
train = step("train", gpu=True, walltime="72h", resumable=True)
```

and save checkpoints (see [Long runs on HPC (Slurm)](../checkpoint.md)), or set `walltime` to the longest run or less.

## Limits of the check

What counts as resumable, in this order: `resumable=` in `pipeline.py`; else what the platform recorded for the step
(see [Evidence from the platform](../lint.md#evidence-from-the-platform)); else nothing: a step with no declaration and no
record is not judged. The longest run comes from your project when you give `--context`; otherwise the built-in default of
2 days applies. It is skipped when the catalogue says your project has no HPC (Slurm) site.
