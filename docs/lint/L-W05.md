# L-W05 DeclaredResumableDidNotResume

**Level: warning.** A step declares that it can continue, but the platform saw a continuation of it start over.

## What it checks

A GPU step sets `resumable=True` (or a lead time such as `resumable="20m"`), and the platform recorded that the latest
continuation of that step did not get past the checkpoint it started from: it made no progress (`NoProgress`) or saved no
new checkpoint before it ended. The message carries the platform's reason and when it was recorded.

The check needs the platform's record of the step, which comes with `--context` (see
[Evidence from the platform](../lint.md#evidence-from-the-platform)). Without a record it stays silent.

## Why it matters

A continuation that restarts from zero repeats the work of the run before it, so a long step never gets further: it burns
its time and budget up to the continuation cap and then stops.

## Example

```python
train = step("train", gpu=True, hpc_time_limit="12h", resumable=True)
```

with a step that saves checkpoints but does not load them when it starts.

## How to fix

Make the step load its checkpoint when it starts and continue from it: save into the folder in `$KAOS_CHECKPOINT_DIR` (or
with `kaos_lib.checkpoint`) and load it back at the start, so a continuation gets past the checkpoint it began from. See
[Long runs on HPC (Slurm)](../checkpoint.md). A later continuation that gets past its checkpoint clears this warning.

## Limits of the check

It judges the latest record only; the record is as fresh as the platform's last continuation of the step.
