# L-E08 StepNotMoved

**Level: error.** A step's code is still written for kaos-lib 0.4 and would fail when it runs.

## What it checks

In the step's folder (`steps/<name>/`):

- code that takes `--params` on its command line, or
- code that reads one of the variables the platform no longer sets (`KUBECORE_RUN_ID`, `CHECKPOINT_BUCKET`,
  `OUTPUTS_REPO`, `KUBECORE_WORKFLOW_NAME`, `KAOS_LIB_LOCK`, `KUBECORE_DATASET_REF`, `KUBECORE_DATASET_COMMIT`,
  `DATASET_REPO`, `DATASET_REF`, `DATASET_COMMIT`, `KUBECORE_STAGED_DIR`), or
- an `app/entry.py` in a folder where nothing calls `step.start()`.

The check reads the files; it never runs them.

## Why it matters

Since kaos-lib 0.5 a step is started as `python -m app.entry` with no arguments. Its config, its run and its
inputs come from `step.start()`, and what it hands on leaves through `step.result()`. Code that waits for
`--params` stops at once; code that reads a variable that is no longer set gets nothing.

## Example

```python
parser.add_argument("--params", required=True)          # no longer passed
run = os.environ.get("KUBECORE_RUN_ID")                 # no longer set
```

## How to fix

```python
from kaos_lib import step

ctx = step.start()            # ctx.params is the config; ctx.run is the run's name
data = step.input("dataset")  # the dataset version the run pinned
step.result(rows=1200)
```

The whole change, with a before and an after, is in [Move to kaos-lib 0.5](../migrate-to-0.5.md).
