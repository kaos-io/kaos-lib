# L-D01 MissingKaosLibArg

**Level: error.** A step uses kaos-lib, but its Dockerfile does not declare `ARG KAOS_LIB_PACKAGE`.

## What it checks

The step imports `kaos_lib` (or its Dockerfile installs kaos-lib with a fixed version) and the Dockerfile has no `ARG KAOS_LIB_PACKAGE`. A step that never uses kaos-lib is not checked.

## Why it matters

The platform chooses the kaos-lib version your step images install and passes it to the build as `--build-arg KAOS_LIB_PACKAGE=...`, together with the label `io.kaos.lib`. It does that only for a Dockerfile that declares the argument. Without it your image keeps whatever version you wrote, the platform cannot move it, and you lose the label that says which version a running step has.

## How to fix

Declare the argument with a default (the version you tested) and install from it:

```dockerfile
ARG KAOS_LIB_PACKAGE="kaos-lib[zitadel]==0.4.0"
RUN pip install --no-cache-dir "${KAOS_LIB_PACKAGE}"
```
