# kaos-lib

The KAOS platform library and the `kaosctl` command: datasets (layouts, versions), run outputs, MLflow, the run
context and the data lock, over kaos-lake (lakeFS). PRD novelcore/kaos#1147 and #1283.

**Documentation: <https://storage.googleapis.com/kaos-dev-511509-kaos-lib/docs/index.html>** (sources in [`docs/`](docs/)): guides, the current install
command of each channel and a CLI reference generated from the code.

## Install

kaos-lib is published to public Python repositories (Google Artifact Registry), not PyPI. Until the first stable
release, install the newest prerelease; [Install](https://storage.googleapis.com/kaos-dev-511509-kaos-lib/docs/install.html) always shows its
exact version:

```bash
pip install --index-url https://europe-west1-python.pkg.dev/kaos-dev-511509/kaos-lib-rc/simple/ \
    --extra-index-url https://pypi.org/simple/ "kaos-lib[zitadel]==<version>"
```

| channel | pip index | made by |
| --- | --- | --- |
| prerelease (`X.Y.ZrcN`) | `https://europe-west1-python.pkg.dev/kaos-dev-511509/kaos-lib-rc/simple/` | every merge to `main` |
| stable (`X.Y.Z`) | `https://europe-west1-python.pkg.dev/kaos-dev-511509/kaos-lib/simple/` | the platform's release train only |

Python 3.9+. Extras: `zitadel` (reading datasets other projects share, from a pipeline step) and `mlflow`.

## In one minute

```bash
kaosctl login
kaosctl dataset create cats --classes cat,kitten          # dataset-cats, yolo layout (--layout none: any files)
kaosctl dataset push ./dataset-cats dataset-cats -m "first images"   # validates, opens a pull request
kaosctl dataset release dataset-cats                      # after the merge: v1
```

```python
from kaos_lib import datasets, outputs

data = datasets.materialize(datasets.DatasetRef.parse("dataset-cats@v1"))   # yolo: data.yaml; raw: the folder
with outputs.run("myapp", "exp1", "run-7") as r:                            # outputs-myapp, one commit per run
    r.save("./ckpt")
    r.finish({"dataset_ref": "dataset-cats@v1"})
```

The command is `kaosctl`; `kaos-cli` is a hidden alias for one release (it prints a notice) and `kubecore` a
deprecated one. Up to 0.2 this was the `kubecore` package:
[Formerly kubecore](https://storage.googleapis.com/kaos-dev-511509-kaos-lib/docs/formerly-kubecore.html).

## Develop

```bash
pip install -e ".[test]" && pytest                          # fake lakeFS, Zitadel and MLflow; no network
pip install -r docs/requirements.txt -e . && mkdocs serve    # the site, with its generated pages
```

The site's CLI reference, version line and install commands are generated by `docs_gen.py` (an mkdocs hook) on
every build; never edit `docs/generated/`. The platform's CI (Argo Workflows) builds the site with
`mkdocs build --strict` on every pull request.
